complete the full iteration count well under their time budget, so the
time check doesn't fire and isn't a determinism source in practice.
Documented as a residual risk; if Verify 1 fails on a slower machine,
the right fix is to drop the time-budget guard rather than add more
seeding.

## Seed scheme (Step 2)

```python
# optimizer.py — module top
def compute_seed(stage, sliders, force_in, force_out, use_race_type_adjustment):
    payload = json.dumps({
        "stage":                   stage,
        "sliders":                 sliders,
        "force_in":                sorted(force_in or []),
        "force_out":               sorted(force_out or []),
        "use_race_type_adjustment": bool(use_race_type_adjustment),
    }, sort_keys=True, default=str)
    return int(hashlib.sha256(payload.encode()).hexdigest()[:16], 16)
```

`force_in` / `force_out` are sorted before hashing to make the seed
stable against list-order variation. `sort_keys=True` makes `sliders`
hashing stable against dict iteration order.

Sub-seed derivation (XOR mask):

| Caller                           | Mask | Purpose                                |
|----------------------------------|-----:|----------------------------------------|
| `optimal` strategy               | 0x1  | SA chain + Plackett-Luce               |
| `depth` strategy                 | 0x2  | "                                      |
| `low-transfer` strategy          | 0x3  | "                                      |
| `lookahead` strategy             | 0x4  | "                                      |
| `estimate_forward_costs` n+1     | 0xA  | forward `fast_optimize` chain          |
| `estimate_forward_costs` n+2     | 0xB  | "                                      |
| forward-cost proxy fast_optimize | 0xF  | only used when no `current_team`       |

When `seed=None` (legacy direct callers), `compute_seed` is not invoked
and sites fall back to the original hard-coded seeds (42 / 123 / 777 /
2026 for SA chains, 42 for forward, 0 for proxy). Backward-compatible.

## Residual risks (intentionally unseeded)

- **Wall-clock early termination** in `fast_optimize` (1s budget) and
  `simulated_annealing` (5s budget). On this dev machine, the iteration
  count is the binding constraint and the time check never fires. On a
  slow / loaded machine, an SA chain could terminate 3 iterations early
  on one run vs another → drift. Not seeded because (a) the right fix
  is removing the time guard, not seeding it, and (b) we have no
  evidence it's biting. Will revisit if a future bit-identical check
  fails on different hardware.
- **Module-level `random.shuffle` fallback** in `get_valid_random_team`
  when `rng=None` (legacy direct-call path). All optimizer.py callers
  now pass `rng=`; left as a fallback for any external caller / future
  code that doesn't.
