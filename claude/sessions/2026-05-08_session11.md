# Session 11 — 2026-05-08

## Five fixes

### Fix 1 — Carousel pill: display only
Removed `setTargetStage(st.stage_number)` from the pill `onclick` handler in
`renderCarousel()`. Pills now update `S.activeStageIndex`, re-render the
carousel, and call `updateHeader()` — they no longer change `targetStage` or
reload odds/intel/optimizer data.

### Fix 2 — Expert weights localStorage
`updateWeight()` now writes `S.expertSources` to
`localStorage('holdet_expert_weights')` before calling `saveWeights()`.
`init()` restores it (after slider restore, before `renderSliders()`) so
custom weights survive a full page reload, in the same pattern as sliders.

### Fix 3 — Remove Inner Ring from expert sources
Removed `{ name: 'Inner Ring', weight: 1.2 }` from `S.expertSources` in
`claude.html`. Removed the matching entry from `expert_sources.yaml`.
`scraper.py` is unchanged — Inner Ring is still scraped; Haiku just no longer
receives a named weight for it (the raw text still feeds the structuring
prompt).

### Fix 4 — Ingemann JSON: regex extraction + tighter prompt
In `/gather-ingemann`:
- Prompt now says **"No text before or after. No markdown fences."** and uses a
  compact one-line template so the model is less likely to pad.
- `json.loads(raw.strip())` replaced with `re.search(r'\{.*\}', raw,
  re.DOTALL)` — extracts the first `{…}` block regardless of surrounding text
  or fences, then `json.loads(m.group())`. Raises `ValueError` with a preview
  if no object is found.

### Fix 5 — Stage results from players API
Rewrote `fetch_stage_results(stage)` in `fetch_riders.py`:
- Probing the nexus `/api/games/{id}/rounds/*` routes found they all return
  Next.js HTML, not JSON. The team page Next.js payload embeds only round
  schedule (start/close/end) — no scoring data.
- The **players API** (`/api/games/{id}/players`) is the only real JSON
  endpoint. After Holdet scores a stage, each player's `points` field carries
  their cumulative total — equal to stage N points for the first stage, or the
  delta for later stages (future work).
- New flow: fetch players API → cross-reference with `stage_N_holdet.json`
  team snapshot → build `rider_results` array (total pts per rider, captain
  flagged) → if any points > 0, write `stage_N_results.json` and return
  `scored: true`.
- `/fetch-stage-results` endpoint updated: returns `{found, data}` instead of
  raw probe dump.
- `fetchStageResults()` in dashboard: on success calls `renderStageResults()`
  directly with the returned data and shows "Stage N not scored yet" if
  `found: false`.

### Fix 5b — team_composition fallback in fetch_stage_results
Both snapshots (`stage_1_holdet.json` and `stage_2_holdet.json`) lacked
`team_composition`: the old snapshot has 184 enrichment riders; the new one
has an empty list (cookie was already expired when `/refresh` ran).

The old code's "elif riders" branch added **all 184 riders** to `team_riders`
— wrong, and would show all 184 with their cumulative points once scored.

Fixed `fetch_stage_results()`:
- Reads `team_composition` from snapshot regardless of format; if empty or
  missing, **tries a live `fetch_team_as_dict()` call**.
- If live fetch succeeds → persists `team_composition` back into the snapshot
  so subsequent calls skip the live fetch.
- If live fetch fails (cookie expired) → logs and falls back to top-20
  scored riders (same safe fallback, clearly logged).

This means the "Fetch Stage Results" button will auto-recover the team
composition the first time it's clicked after the user refreshes their cookie.
