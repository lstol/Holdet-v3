# Session 3 — 2026-05-06

## What was built
- `claude/dashboard/claude.html` — full single-page expert dashboard:
  - Header: stage title, bank balance, data status, refresh button
  - Stage carousel: pills for S1–S21, prev/next arrows, SVG elevation profile (terrain-based)
  - Stage type sliders: n+1 / n+2 / n+3 columns (Sprint/Hilly/Hard GC/Mixed, sum validator)
  - Expert weights column: per-source sliders (0.5–2.0), writes to server on change
  - Bookmaker odds table: editable rows (rider, Win%, Top3%), add/delete row
  - Intel notes: free-text textarea
  - Candidate teams: Run optimizer button → builds structured prompt → sendPrompt() or clipboard fallback
  - Rider table: all 210 riders, search + type filter pills, dynamic Tier (A/B) from n+1 sliders,
    P(win) from odds table, Force In / Force Out toggles, status badge
- `claude/engine/server.py` — local Flask server:
  - POST /refresh → runs fetch_riders.py, returns {status, timestamp, rider_count}
  - POST /save-weights → writes expert_sources.yaml
  - GET /snapshot → returns latest stage_N_holdet.json
  - GET /files/<path> → serves any repo file as static
  - GET /dashboard → serves claude.html

## Decisions made
- Dashboard is single-page, no tabs, expert-facing (13px base, dense layout)
- Run optimizer fires sendPrompt() — Claude responds in chat, not in dashboard render target
- Rider type derived from terrain_affinity (specialist_classification field unpopulated in v1 data)
- Tier recomputes dynamically on every n+1 slider change
- Stage profiles rendered as SVG paths from terrain_classification field
- Server not required to load data — dashboard falls back to file:// paths, then mock data
