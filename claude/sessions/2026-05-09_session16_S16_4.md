# Session 16 — Task 4: Lookahead objective refactor

## TL;DR

Lookahead's internal SA objective now matches the user-facing
transfer-adj EV metric. Pre-refactor it skipped `tc_current` (the
cost of switching INTO the candidate team from the user's actual
team), which meant the SA happily proposed teams with expensive
current-stage transfers in pursuit of marginal forward optionality.
Post-refactor the SA picks teams that are 19k better on the headline
metric and 114k ahead of Low-transfer, while non-Lookahead strategies
remain bit-identical.

## Pre-refactor objective

[optimizer.py:722-725](claude/engine/optimizer.py:722) (before):

```python
elif objective == 'lookahead':
    tc_n1 = compute_transfer_cost(team, team_n1 or []) if team_n1 else 0
    tc_n2 = compute_transfer_cost(team_n1 or [], team_n2 or []) if team_n1 and team_n2 else 0
    return base_ev - tc_n1 - (LOOKAHEAD_DISCOUNT * tc_n2)
```

Two terms penalized: cost from candidate → team_n1, and cost from
team_n1 → team_n2 (×0.7). Missing: cost from `current_team` →
candidate. So the SA could move "for free" (in objective space)
from the user's actual roster into any candidate, regardless of how
expensive that transition was.

## Post-refactor objective

[optimizer.py:722-735](claude/engine/optimizer.py:722) (after):

```python
elif objective == 'lookahead':
    # S16-4: align internal objective with the user-facing transfer-adj EV
    # metric. Coefficients (1.0 / 1.0 / 0.7) match the result-assembly's
    # 'total_forward_cost' field exactly.
    tc_current = compute_transfer_cost(current_team or [], team) if current_team else 0
    tc_n1      = compute_transfer_cost(team, team_n1 or [])      if team_n1 else 0
    tc_n2      = compute_transfer_cost(team_n1 or [], team_n2 or []) if team_n1 and team_n2 else 0
    return base_ev - tc_current - tc_n1 - (LOOKAHEAD_DISCOUNT * tc_n2)
```

Plumbing: added `current_team=None` keyword to `compute_objective`
([optimizer.py:704](claude/engine/optimizer.py:704)) and threaded it
through `simulated_annealing`
([optimizer.py:737](claude/engine/optimizer.py:737)) and the
strategy dispatcher's call site
([optimizer.py:993](claude/engine/optimizer.py:993)). Other
strategies ignore the new parameter (their objective branches don't
reference it), so they remain bit-identical.

## RNG plumbing

No surprises. Per-strategy XOR-mask seed (0x4 for lookahead) still
flows through `simulated_annealing` and `simulate_stage` unchanged
from S16-3. The new `current_team` parameter is passed by reference
and read-only inside `compute_objective`, so it doesn't perturb any
RNG draw or iteration count. Bit-identical re-run verification
(Verify 1) confirms.

  gains `current_team=None` parameter; `lookahead` branch now
