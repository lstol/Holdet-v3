# Session 15 — Handoff B: current team from results file

## Diagnosis

Where current team was sourced before:
- `server.py:386-394` `run_optimizer_py` read `stage_{stage}_holdet.json`
  (the **target-stage** holdet snapshot), pulled `team_composition`, and matched
  against `riders.json` with exact equality:
  ```python
  current_team = [r for r in active_riders if r['name'] in current_team_names] or None
  ```
- For target stage 2, `stage_2_holdet.json` had empty `team_composition` (it gets
  populated only after the user refreshes from Holdet post-stage-1), so the
  optimizer ran with `current_team=None` (zero transfer cost — false picture).
- Even when `team_composition` was present (stage 1), one rider name diverged
  in case between sources: `stage_1_holdet.json` and `stage_1_results.json`
  both spell **"Dries van Gestel"** (lowercase v); `riders.json` spells
  **"Dries Van Gestel"** (capital V). Exact-equality match dropped him → 7/8.

## What changed

`server.py` `run_optimizer_py` now:
- Keeps reading `stage_{stage}_holdet.json` for `bank_balance` only.
- Reads the team that just raced from `stage_{stage-1}_results.json`
  (the public Holdet API snapshot — authoritative names + always 8 riders
  when the stage is scored).
- Match strategy: exact name → fall back to case-insensitive lookup
  against `active_riders`. Anything still unmatched is logged as a warning
  and surfaced on the response as `name_match_warnings`.
- Response now includes `current_team` (8 rider dicts) and
  `name_match_warnings` (list, empty on success).
